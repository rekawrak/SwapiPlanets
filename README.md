## Кратко
* Состояние экрана списка собирается из нескольких потоков
* Отдельно экран избранного: **`combine`** (id из Room, сортировка из DataStore, сигналы refresh) и **`flatMapLatest`** для загрузки деталей по сети по актуальному списку id.
* Итоговый **`UiState`** для списка — результат **`combine { … }.stateIn`**
* На списке используются не меньше трёх независимых источников, И Room, и DataStore идут из **data layer**, а не создаются только во View при композиции
* **Объединение:** **`combine`**, **`merge`**
* **Преобразование / управление:** **`debounce`**, **`distinctUntilChanged`**, **`flatMapLatest`**, **`map`**
* **`StateFlow`** — долговременное состояние для экрана (`state`, строка поиска, флаги UI)
* **`SharedFlow`** — поток действий пользователя (повторная загрузка / refresh)

## 

У SWAPI для первой страницы списка планет **нет отдельного поискового API**; после **`debounce`** выполняется **клиентская** фильтрация по имени по уже загруженным данным. Реактивная часть (debounce + объединение с Room и DataStore) при этом сохраняется.
